Agentic Bug Hunter

A security agent that hunts vulnerabilities in smart contracts and protocols — and proves its findings instead of just claiming them.
Entry for zkVerify Agent Games, Wildcard track.

The problem

AI bug hunting is easy to fake. An agent can flood a programme with plausible-looking findings that waste triagers' time, or hallucinate a vulnerability that doesn't exist. For a hunter, an unproven finding is worthless; for a protocol team, it's noise. What both sides need is a finding that survives being attacked.

Who it helps

Bug-bounty hunters who want to file findings that hold up under triage, and protocol teams who want signal, not volume: every finding this agent files carries machine-checkable evidence and a validator verdict.

How it works

  1. Scope-first. Never touches a target without an explicit programme and scope.
  2. Recon. subfinder, httpx, nuclei, katana, amass, gau and friends map the target.
  3. Hunt. An AI brain (Gemini via LiteLLM, Ollama qwen3:4b fallback) reads code and proposes candidates.
  4. 7-Question Gate. Every candidate must survive seven validation questions.
  5. Adversarial verifier. A second, independent reviewer tries to refute each finding. Verdicts: confirmed / needs_validation / rejected.
  6. Deterministic validators. verifier/validate-findings.cjs and validate-coverage-ledger.cjs check the report before anything is filed.

Evidence it works

Report XE-9554, filed 12 Nov 2026 against the XE Network bounty programme: 2 findings (1 High, 1 Medium claimed), both reproduced in the local harness (4/4 checks PASS) and both passing the deterministic validators. Status: awaiting triage.

Live demo

The agent's demo API runs locally (Node, zero dependencies):

node endpoint/server.cjs 8080
curl localhost:8080/        # agent card
curl localhost:8080/health  # liveness
curl localhost:8080/report  # redacted sample report

Machine-readable agent card: agent-card.json

zkVerify

No zkVerify integration is shipped yet, and none is claimed. Findings are already machine-checkable claims (schema + validator verdicts); making a validator verdict provable on-chain via zkVerify is the natural next step.
